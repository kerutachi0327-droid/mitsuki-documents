# OTOMIZU スケジュール管理 — クラウド環境設定

作成：2026-10-27

## 前提（仮決め・変更可）

| 項目 | 仮決め | 理由 |
|---|---|---|
| 公開先 | Netlify | 既にアカウント接続済み（11サイト運用中）。セッションから直接デプロイできる |
| DB・ログイン | Supabase（Postgres + Auth） | 個人事業主ごとにログイン、行単位で「自分の予定は編集・他人は閲覧のみ」を制御できる（RLS）。無料枠あり |
| 画面 | Webアプリ（スマホ対応） | 外出先から各自が確認・入力 |
| リポジトリ | `otomizu-schedule` | みつき資料リポジトリは Cloudflare Pages でルート公開中のため分離 |

## 「新しい環境」ダイアログに入れる値

### 名前
`otomizu-schedule`

### ネットワークアクセス
- レベル：**カスタム（Custom）**
- 許可するドメイン（1行1つ）：
```
*.supabase.co
api.supabase.com
api.netlify.com
*.netlify.app
```
- **「Also include default list of common package managers」にチェック**（npm 等を残す）
- 補足：GitHub と MCP コネクタ（Netlify / Google Calendar 等）の通信はこの許可リストを通らないので追加不要

### ネットワークシークレット（キーはチャットに貼らない）
| 名前 | 許可サイト | ヘッダー | 値 |
|---|---|---|---|
| Netlify | `api.netlify.com` | `Authorization: Bearer` | Netlify の Personal access token |
| Supabase 管理 | `api.supabase.com` | `Authorization: Bearer` | Supabase の Access token |

※ Supabase プロジェクト作成後に `service_role` キーを使う場合は `<project-ref>.supabase.co` 用に、ヘッダー `apikey`（Prefix なし）で追加

### セットアップスクリプト
リポジトリ直下の `setup.sh` を「ファイルを選択」で読み込む（Netlify CLI・Supabase CLI を導入。5分以内で終わりキャッシュされる）

### 環境変数（秘密でないものだけ）
```
NODE_ENV=development
TZ=Asia/Tokyo
```

## 設定後の確認
新しいセッションで「環境確認して」と指示 → `netlify --version` / `supabase --version` / Supabase・Netlify への疎通を確認
